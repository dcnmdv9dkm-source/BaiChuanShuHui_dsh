`BaiChuanShuHui_dsh` is a plugin for **DeepSeek Harness**. It exposes the
BaiChuanShuHui statistical engine — a zero-dependency Python CLI with **30+ subcommands**
covering data cleaning, descriptive statistics, hypothesis testing, ANOVA, regression,
IRT, CFA, SEM, power analysis, and discipline-aware visualization — as **native model-facing
tools**. When you ask DeepSeek to clean a dataset, run an ANOVA, or draw a discipline-specific
chart, the harness calls the matching tool, which runs the local Python kernel and returns the
result as structured JSON.

## How it works

| Layer | What happens |
|---|---|
| Model | Sees 30+ typed tools (`bcsh_clean`, `bcsh_anova`, `bcsh_regress`, `bcsh_viz`, …) with real JSON-Schema parameters. |
| Harness | Routes the tool call to this plugin's `execute()`. |
| Plugin | Spawns a thin Python bridge (`python/bcsh_run_tool.py`), which introspects the kernel and runs the subcommand. |
| Kernel | `skill_runtime.py` performs the computation locally and prints a unified JSON result. |

The plugin does **not** replace the main model or any adapter. Tool schemas are generated by
introspecting the kernel's own `argparse` at load time, so the 30 tools always stay in sync with
the engine — no hand-maintained schema.

The engine auto-detects a Python interpreter with `numpy` / `scipy` / `scikit-learn` and enables
more precise algorithms; with plain `python3` it degrades gracefully to exact, dependency-free
implementations.

## Install

Use the plugin manager built into DeepSeek Harness:

```sh
npx @deepseek-ai/dsh plugin --profile web add github:dcnmdv9dkm-source/BaiChuanShuHui_dsh
```

Restart Harness. The plugin then registers its tools automatically; no settings card is required.
Ask the model something like *"清洗 data.csv 中的缺失值与异常值"* or *"对 score 按 group 做单因素方差分析"*
and it will call the matching tool.

> DeepSeek Harness is still in Developer Preview. This release targets `0.1.0-rc.6` exactly.
> If your Harness is on a different preview build, bump the `peerDependencies` in `package.json`.

## Configure

The plugin needs a Python interpreter and the bundled kernel. Both are auto-detected, but you can
override them with environment variables in the Harness launch environment (or `$DSH_HOME`'s env):

| Variable | Default | Meaning |
|---|---|---|
| `BCSH_PYTHON` | `python3` | Python interpreter used to run the kernel. Point it at a venv with `numpy`/`scipy`/`scikit-learn` for the most precise algorithms. |
| `BCSH_KERNEL_DIR` | `<plugin>/python` | Directory containing `skill_runtime.py`. Use this to point at an external/updated kernel instead of the bundled one. |
| `BCSH_TIMEOUT` | `300` | Per-call timeout (seconds) for the kernel subprocess. |

No API keys, no network egress, and nothing secret to store.

## Security boundary

- The kernel runs **locally** as a subprocess; it only reads the input files and writes the output
  paths the model explicitly passes (`--input-file`, `--output`, …).
- The kernel performs **no network calls**. The only network traffic is the DeepSeek API request
  made by the Harness itself, not by this plugin.
- Tool arguments are validated by the kernel's own `argparse` before any computation runs; unknown
  keys are ignored, not executed.
- Long-running calls honor cancellation: an aborted tool call kills the kernel subprocess via the
  harness `AbortSignal`.
- Bundled Python is the only code executed; the plugin adds no third-party runtime beyond the
  engine itself.

## Development

```sh
pnpm install
pnpm build      # tsdown → lib/index.js
pnpm typecheck  # tsc --noEmit (needs @deepseek-ai peer types to fully check)
```

The Python side is testable on its own:

```sh
python3 python/bcsh_run_tool.py --list          # list 30+ subcommands
python3 python/bcsh_run_tool.py --emit-tools    # print the JSON-Schema tool definitions
python3 python/bcsh_run_tool.py clean '{"input":"data.csv"}'
```
